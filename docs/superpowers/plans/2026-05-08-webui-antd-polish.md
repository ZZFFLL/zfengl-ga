# GenericAgent WebUI AntD Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Upgrade `frontends/webui` from a competent Tailwind/Radix chat UI into a more polished Ant Design-backed GA workbench while preserving the existing GA streaming, execution-log, and conversation behavior.

**Architecture:** Use Ant Design for system interaction primitives and global design tokens, while keeping the GA-specific chat, sidebar, and execution rendering as custom React views. Do not move display-routing responsibility from `frontends/webui_server.py` into the browser; the browser remains a presentation layer for already-split chat content and execution metadata.

**Tech Stack:** React 18, TypeScript, Vite, Tailwind CSS, Ant Design v5, lucide-react, react-markdown, remark-gfm, existing Python WebUI server/SSE contract.

---

## Design Direction

Use `ui-ux-pro-max` as the visual judgment layer and Ant Design as the interaction component layer.

**Product type:** AI agent workbench / developer productivity console.

**Target feel:** calm, professional, dense enough for repeated work, not a marketing landing page.

**Visual rules:**
- Prefer neutral workbench surfaces, crisp borders, deliberate spacing, and restrained shadow.
- Avoid large decorative gradients, floating decoration, hero-card compositions, and one-note blue/purple gradients.
- Keep the chat body readable first; controls should feel precise but not visually louder than the conversation.
- Use one icon family in operational buttons; this repo already uses `lucide-react`, so keep it.
- Use AntD tokens to align control height, radius, focus, popup, modal, drawer, and dropdown behavior.

**Hard boundaries:**
- Do not modify `frontends/webui_server.py` unless a visual change reveals an actual backend contract bug.
- Do not modify GA core files, SSE protocol, execution parsing, or conversation persistence.
- Do not remove execution process visibility. Execution turns and tool calls must stay visible in the message flow.
- Do not edit external dependency project code.

```tsx
function askText(title: string, defaultValue = "") {
  return new Promise<string | null>((resolve) => {
    let nextValue = defaultValue;
    modal.confirm({
      title,
      icon: null,
      width: 460,
      okText: "确认",
      cancelText: "取消",
      autoFocusButton: "ok",
      content: (
        <Input
          defaultValue={defaultValue}
          autoFocus
          onChange={(event) => {
            nextValue = event.target.value;
          }}
          onPressEnter={() => {
            const value = nextValue.trim();
            resolve(value || null);
            modal.destroyAll();
          }}
        />
      ),
      onOk: () => {
        resolve(nextValue.trim() || null);
      },
      onCancel: () => {
        resolve(null);
      },
    });
  });
}

function confirmAction(options: { title: string; content?: string; danger?: boolean }) {
  return new Promise<boolean>((resolve) => {
    modal.confirm({
      title: options.title,
      content: options.content,
      okText: "确认",
      cancelText: "取消",
      okButtonProps: options.danger ? { danger: true } : undefined,
      onOk: () => resolve(true),
      onCancel: () => resolve(false),
    });
  });
}
```

Import `Input` from `antd` for this helper.
